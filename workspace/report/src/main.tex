\begin{abstract}
This report presents the design and physical implementation of a dual-core machine learning accelerator tailored for the attention mechanisms in modern transformer models. The architecture features an asynchronous clocking scheme that distributes matrix multiplication and normalization across a dual-core setup. A hardware-optimized, sparsity-aware Softmax (SFP) engine is introduced, which utilizes cross-core sum exchange and bypasses redundant computations to improve energy efficiency. To overcome critical timing bottlenecks, we applied rigorous architectural optimizations—including a pipelined long divider and adder tree—reducing the critical path delay from over 24\,ns to under 1.0\,ns and shrinking the full-chip standard cell area by 47.8\%. Furthermore, we developed a highly scalable, Makefile-driven verification framework anchored by a custom \texttt{.mingu} shell. This framework seamlessly bridges behavioral RTL simulations with large-scale, automated post-PnR gate-level simulations. Validated through a TSMC 65nm hierarchical physical design flow, the accelerator achieves zero timing violations and demonstrates fully functional, tape-out-ready physical layouts.
\end{abstract}

\section{Introduction}
Attention mechanisms form the computational backbone of modern transformer models, but their reliance on intensive matrix multiplications (MatMul) and row-wise Softmax normalizations presents significant throughput and memory bottlenecks. To address these challenges, this project proposes a dual-core hardware accelerator designed specifically for efficient attention computation.

The architecture partitions the workload across two independent cores communicating via asynchronous FIFOs, enabling flexible cross-domain scheduling. To alleviate the Softmax bottleneck, we developed a Sparsity-Aware Softmax (SFP) engine that dynamically skips computations for insignificant attention scores, reducing dynamic power and latency. Given the complexity of the asynchronous, dual-core architecture, we adopted a rigorous, incremental design methodology—progressing from basic single-core RTL to a tape-out-ready, full-chip hierarchical physical layout. This report details the architectural innovations and the physical implementation milestones that achieved zero timing violations under a 1.0\,ns clock constraint.

\section{Proposed Architecture}

\subsection{\underline{\textnormal{Dual-Core System \& Asynchronous Clocking}}}
To maximize throughput, the accelerator is partitioned into two distinct processing cores (Core 0 and Core 1). Each core operates in its own clock domain (\texttt{clk0} and \texttt{clk1}) to simulate realistic system-on-chip (SoC) environments where different functional blocks might run at different frequencies. Data and control signals are securely transferred between the two clock domains using asynchronous FIFOs (Async FIFO). This cross-domain communication (CDC) ensures that matrix chunks processed by one core can be synchronized with the other core without meta-stability issues, particularly during the global sum accumulation required for Softmax normalization.

\subsection{\underline{\textnormal{Core Controller \& Data flow}}}
Each core features an independent controller and a memory map (\texttt{reg\_map}) to handle top-level configurations. The controller manages the data flow between the Query Memory (QMEM), Key Memory (KMEM), the MAC array, and the SFP engine based on the defined operation mode (\texttt{op\_mode}):
\begin{itemize}
    \item \textbf{Mode 1 (MatMul Only):} The core multiplies data from QMEM and KMEM using the MAC array, and directly stores the result into the Partial Sum Memory (PMEM).
    \item \textbf{Mode 0 (MatMul + Normalization):} Data from QMEM and KMEM are multiplied, and the resulting partial sums are fed into the SFP engine. The normalized outputs are then written back to either PMEM or KMEM, dictated by \texttt{sfp\_write\_to\_pmem} and \texttt{sfp\_write\_to\_kmem} flags.
\end{itemize}
The controller automatically generates status flags (e.g., \texttt{qmem\_free}) to notify upper-level modules when memory banks are available for new data, enabling efficient cycle-saving data prefetching.

\subsection{\underline{\textnormal{Sparsity-Aware Softmax (SFP) Engine}}}
The SFP row block is responsible for normalizing one row of the MAC array outputs. The normalization process is divided into two pipelined phases:
\begin{enumerate}
    \item \textbf{Accumulation (acc):} When \texttt{acc\_start} is pulsed, the engine computes the row energy $S_{i} = \sum_{j} |sfp\_in[j]|$ using an adder tree. The sum is temporarily stored in an internal FIFO, and \texttt{acc\_done} is asserted upon completion.
    \item \textbf{Division (div):} During the division phase, triggered by \texttt{div\_start} (which is gated by a \texttt{div\_busy} signal to prevent overlapping operations), the engine retrieves the local sum from the FIFO and adds it to the sum from the other core (\texttt{sum\_in}). It then computes the normalized output:
    \begin{equation}
        sfp\_div\_out[c] = \text{trunc}\left(\frac{|sfp\_in[c]| \ll out\_shift}{S_{local} + sum\_in}\right)
    \end{equation}
    Upon finishing the division, a \texttt{div\_done} pulse is generated to indicate that the normalized results are valid.
\end{enumerate}
To further optimize performance, a sparsity gating mechanism is implemented. If the computed row energy $S_{i}$ is strictly less than a configurable \texttt{SFP\_THRESHOLD}, the engine bypasses the division and outputs all zeros. This effectively filters out negligible attention scores, conserving dynamic power.

To systematically conquer the design complexity, the project was executed in six sequential milestones.

\subsection{Step 1: Single Core RTL, Synthesis \& PNR}
The baseline single-core design was implemented and verified first. This step established the core infrastructure, including the MAC array and the basic controller.
Post-PnR layout, GLS waveform, and terminal output for the single-core design are shown below. Table~\ref{tab:s1} summarizes power, WNS, and DRC across implementation steps, including Step~1.

To validate the flexibility of the single-core design, we separately tested the QK product and the V--Norm product using the same computation path. This demonstrates that the design can support both stages of the attention computation, providing a verified foundation for later steps where these operations are connected into a more complete pipeline.

In addition, minor modifications were made to the professor-provided testbench to align with our implementation. Specifically, the DUT was updated from \texttt{fullchip} to \texttt{core}, along with adjustments to parameter settings and data packing format. An automatic golden result comparison (PASS/FAIL) mechanism was also added. These changes improve verification efficiency while preserving the intended functionality. Figure~\ref{fig:s1_term} shows the terminal output demonstrating the golden result comparison mechanism, while Figure~\ref{fig:s1_wave} presents the corresponding waveform of the design.




\subsection{\underline{\textnormal{Step 2: Output Normalisation}}}
The single-core MAC array was integrated with the SFP (Softmax with Fixed-Point) row block. The SFP block normalizes the partial sums row by row in two phases: \textit{accumulation} and \textit{division}. 

During the \textbf{accumulation (acc)} phase, the block calculates the row energy by summing the absolute values of the incoming partial sums from the MAC array ($S_i = \sum |sfp\_in[j]|$). 

In the \textbf{division (div)} phase, each absolute partial sum is divided by the global row sum to produce the normalized output. To support multi-core scaling, the global sum combines the local core's sum ($S_i$) with the sum from the other core ($sum\_in$). 

Since the theoretical output of the normalization falls within the range $[0, 1]$, integer division would yield zero for almost all values. To address this, a fixed-point scaling mechanism is introduced using the \texttt{out\_shift} parameter. The numerator is logically left-shifted by \texttt{out\_shift} bits before division: 
\[ sfp\_div\_out[c] = \text{truncate}\left(\frac{|sfp\_in[c]| \ll out\_shift}{S_i + sum\_in}\right) \]
This shift defines the fractional precision of the output. For example, a default \texttt{out\_shift = 7} allocates 7 bits for the fractional part, mapping the $[0, 1]$ range to $[0, 128]$ in the 8-bit output. Behavioral simulations verified that these calculations correctly normalize the partial sums. Figure~\ref{fig:s2_wave} shows the simulation waveform demonstrating the functional correctness of the Step 2 design, with the output matching the expected normalized values.


\subsection{\underline{\textnormal{Step 3: Hierarchical Synthesis of Single Core}}}
Memory macros (SRAMs for QMEM, KMEM, and PMEM) were incorporated into the core.
A hierarchical synthesis and PnR flow was adopted to manage the physical
placement of the SRAM macros alongside standard cells. Each SRAM was synthesized
and placed-and-routed independently with the top metal layer restricted to M4,
with data input pins on the bottom edge and output pins on the top edge. The
extracted Liberty timing models and LEF files from SRAM PnR were used during
core-level synthesis and PnR, with SRAM instances treated as black boxes via the
\texttt{dont\_touch} attribute. Gate-level simulation confirmed functional
correctness with zero mismatches across all 8$\times$8 QK and VN output values.



\subsection{\underline{\textnormal{Step 4: Hierarchical Synthesis of Dual-Core}}}
Two single-core instances were integrated into a top-level fullchip module, with each core processing 8 of the 16 attention vectors in parallel. Cross-domain partial sum exchange for global normalisation was implemented via a custom Gray-code asynchronous FIFO with a sample-and-hold register at each core input. Both a lockstep (single clock) and a dual-clock (1.0 ns / 1.2 ns) configuration were validated at gate level against software-computed golden references, with the dual-clock mode included as an extension beyond the base deliverable. Table~\ref{tab:s1} captures the power, WNS, and DRC measurements. Figure~\ref{fig:s4_fullchip_layout} shows the dual-core fullchip layout. Figures~\ref{fig:s4_wave} and~\ref{fig:s4_wave1} present the GLS waveforms for non-lockstep and lockstep operation, respectively. Initial synthesis results highlighted a massive timing violation (Worst Negative Slack $\approx$ -23.9\,ns) primarily due to deep combinational logic in the SFP row's absolute sum and division calculations. To achieve timing closure for a 1.0\,ns clock period, we added 3-stage pipeline in the accumulation and also added \texttt{-retime} to meet the timing requirement:

\begin{itemize}
    \item \textbf{Divider Optimization:}
    Previous synthesis timing reports indicate that the native Verilog / divider is the bottleneck of achieving 0 WNS. 
    Therefore, we implemented 2 possible upgrades of our division module. 
    \begin{enumerate}
    \item 6-stage pipelined long divider
    \item 10-cycle MCP native Verilog / divider
    \end{enumerate}
    Besides, the 2 designs share a common handshake interface with the core (\texttt{div\_start}, \texttt{div\_busy}, \texttt{div\_done}); macros (\texttt{SFP\_LONGDIV}, \texttt{SFP\_MCP}, \texttt{VANILLA}) are also defined to compile and synthesis the designs with ease.
    
    \textbf{Results.} 
    Both designs passed the Hold/Setup time check and the gate-level simulation. Nonetheless, we have to select the optimal design for PnR. Hence, we compare the synthesis result in Figure~\ref{fig:s5_divComparison}. 
    The 6-staged pipelined long division hardware outperforms the 10 cycle MCP Verilog / divider with ($\sim$23\%) lower area, slightly lower power, and much shorter synthesis time (10 min vs. 45 min).
    Thus, we selected the pipelined long divider for PnR.
    



    \item \textbf{Pipelining - Adder Tree Optimization:} The row energy accumulator was redesigned as a 3-stage pipelined reduction tree. After the 8 parallel multipliers, one pipeline stage captures the multiplication results, the next stage performs four pairwise additions, and the final stage reduces the partial sums to produce the accumulated row energy. Table~\ref{tab:s5_timing} presents a before-and-after area and timing comparison for the repipelined blocks (fullchip, MAC array, and SFP row).

    \item \textbf{Chip Interface Design and Internal Control:} 
    The chip interface is redesigned not only to remove redundant signals, but also to hide unnecessary internal details. The goal is to provide an intuitive and self-consistent interface, allowing users to operate the chip without understanding internal dataflow or timing dependencies. Each core is independently controlled, and we describe usage from the perspective of a single core.
    

    \textbf{Example Flow (MULT+NORM+READ):} 
    Write Q/K via \texttt{inst\_ext} $\rightarrow$ set \texttt{mode} $\rightarrow$ assert \texttt{start} (locks memory) $\rightarrow$ compute $\rightarrow$ unlock $\rightarrow$ read PMEM.
    The above example involves external memory instructions and mode configuration. Refer to Figure~\ref{fig:s5_Controller_user_manual_spec} for details.
    
    \textbf{Design Insights.}
    \begin{itemize}
        \item Flexible data loading; fixed execution schedule, simplifying hardware control while preserving user flexibility.
        \item Deterministic memory locking with hardware-enforced protection, eliminating user-side synchronization.
        \item Unified interface (4 commands) with mode-driven dataflow, reducing control complexity and enabling data reuse.
        \item Implicit pipeline support, allowing overlap of computation and data loading for higher throughput.
    \end{itemize}

    \item \textbf{Normalization Block Protocol: }
The Alpha implementation exposes a two-phase, row-local transaction. For each row, the partial-sum vector on \texttt{sfp\_in} is valid for a single cycle coincident with a one-cycle \texttt{acc\_start} pulse; the same vector must be reapplied for one cycle coincident with \texttt{div\_start}. The accumulation phase for a given row completes before division begins for that row (internal FIFO ordering). The cross-core partial sum \texttt{sum\_in} is asserted on the cycle immediately following \texttt{div\_start}, modeling a one-cycle read delay on the interconnect. A new \texttt{div\_start} is permitted only when \texttt{div\_busy} is low, excluding overlapping divide operations. The normalized result \texttt{sfp\_div\_out} is qualified by a one-cycle \texttt{div\_done} pulse. Division uses $S_{\mathrm{local}}+\texttt{sum\_in}$ as divisor, where $S_{\mathrm{local}}$ is the row energy from the acc phase; the block outputs all zeros if $S_i < \texttt{SFP\_THRESHOLD}$ or if the input row is identically zero.


\item Dual-Core Verification (Lockstep and Non-Lockstep). Functional correctness of the dual-core integration was verified in both lockstep (single shared clock) and non-lockstep (1.0 ns / 1.2 ns asynchronous) configurations at gate level, demonstrating robustness of the asynchronous CDC protocol across both operating modes.
    

\end{itemize}
These architectural optimizations successfully between Step 4 and 5 reduced the WNS (Setup)from $\sim$-9.106\,ns down to 0.001\,ns, and WNS (Hold) from eliminating $\sim$-4.713\,ns down to 0.037\,ns, all timing violations. The Power increased from 29.68 mW to 54.21 mW. Table~\ref{tab:s1} provides the comparison parameters for all steps.



\subsection{Step 6: Sparsity-Aware Attention}
The final milestone validated the sparsity-aware feature. By injecting highly sparse matrices, we confirmed that the SFP engine correctly identifies rows below \texttt{SFP\_THRESHOLD} and outputs zeros, bypassing unnecessary long division cycles.

\textbf{Sparsity Definition and Threshold Calibration.}
We define the row-wise accumulation as:
\begin{equation}
S_i = \sum_{j} \left| (QK^T)_{i,j} \right|.
\end{equation}
A row is skipped if $S_i < T$, where $T$ corresponds to \texttt{SFP\_THRESHOLD}. To achieve a target sparsity of 30\%, $T$ is obtained from the empirical distribution of $S_i$ using Monte Carlo simulation over 10{,}000 datasets:
\begin{equation}
T = \text{Percentile}_{30}(S),
\end{equation}
ensuring approximately 30\% of rows satisfy $S_i < T$. The sparsity is defined as:
\begin{equation}
\text{sparsity} = \frac{1}{N} \sum_i \mathbf{1}(S_i < T).
\end{equation}

\textbf{RTL Skip Mechanism and Verification.}
In RTL, the accumulation from both cores is combined as \texttt{sum\_2core}, and the skip condition is evaluated via \texttt{sum\_2core < SFP\_THRESHOLD}. When triggered, the divisor is gated to zero (\texttt{sum\_2core\_gated}) and fed into the divider (e.g., \texttt{div\_longdiv}), allowing its FSM to bypass computation and force zero outputs without modifying the control flow. The same criterion is replicated in the testbench to count skipped rows and compute sparsity. Figure~\ref{fig:s6_layout} shows the corresponding layout.

\textbf{Results.}
Using 10{,}000 sample in \texttt{threshold.py} searching threshold, the threshold for sparsity we get is 169503. With this threhold, we test test with 1000 other random generated data ,and the measured sparsity we get is 34.975\%, close to the 30\% target. The deviation is attributed to distribution variance, demonstrating that the threshold generalizes well and that the RTL correctly implements sparsity-aware skipping. Figure~\ref{fig:s6_wave} and Figure~\ref{fig:s6_term} show the corresponding waveform and terminal output.


\section{Plus Alpha Implementations}
To facilitate rapid development and reliable testing of the dual-core design, a robust Makefile-driven flow and shell-based verification infrastructure were established.
\subsection{\underline{\textnormal{Design Methodology and Verification Infrastructure}}}
\begin{itemize}

    \item \textbf{Production System Setup (Makefile-based Flow):} 
    A centralized Makefile manages RTL simulation, GLS, and synthesis, with key parameters (e.g., target, clock, configuration) specified via command-line arguments for reproducible and rapid iteration. A summary is shown in Table~\ref{tab:makefile_cmds}.
    The \texttt{USER\_DEFINES} variable (persisted in \texttt{USER\_DEFINE\_TASK\_VARS}) enables flexible architectural exploration (e.g., \texttt{SFP\_LONGDIV}, \texttt{SFP\_MCP}, \texttt{SFP\_THRESHOLD}) without modifying RTL or scripts. Since it propagates to both simulation and synthesis, it ensures consistency between RTL and final netlist.
    

    \item \textbf{Randomized Input Generation:} 
    We support automatic generation of randomized test patterns for functional verification. 
    The system detects missing pattern files and generates them on demand, allowing large-scale testing without manual data preparation. 
    This improves coverage and helps uncover corner-case bugs under diverse input conditions.

    \item \textbf{.mingu Shell (Matrix INstruction Generation Utility):}
    A scriptable simulation shell built on top of the Makefile flow, providing a
    high-level interface (\texttt{writeQ}, \texttt{simulate}, etc.) to control the
    testbench. It supports configuration/execution phases, variable substitution,
    and \texttt{for}-loops for automated testing across \texttt{Alpha} and \texttt{Step6}.
   

   For example, Fig.~\ref{fig:s5_MinguVeri} shows generation of 100 randomized patterns and output verification using \texttt{.mingu}. Its well-defined interface allows high-level commands to map directly to hardware states, enabling scalable testing from single-core RTL to full-chip Post-PnR without new testbenches.
   
\end{itemize}

\section{Conclusion}
This project successfully demonstrates the design, implementation, and physical realization of a dual-core attention accelerator. By partitioning the system into asynchronous domains, we enabled flexible inter-core data exchange. Through the introduction of a Sparsity-Aware SFP engine, computations on insignificant data are bypassed, promoting energy efficiency. Most importantly, critical timing bottlenecks were identified and resolved via rigorous RTL repipelining, ensuring the design easily meets the 1.0\,ns clock constraint in a TSMC 65nm process. The progressive, step-by-step verification methodology guaranteed robustness from the behavioral level down to post-PnR gate-level simulations, confirming the design's readiness for physical fabrication.

\section{Mingu Shell Command Reference}
\label{sec:appendix_mingu}

The \texttt{.mingu} shell abstracts the complexity of cycle-accurate testbenches into a high-level scripting language. Below is the complete reference of supported commands, categorized by execution phase.

\subsection{Phase 1: Shell Configuration Commands}
These commands must be executed \textbf{before} \texttt{fix\_set}. They configure the underlying simulation backend, Makefile parameters, and output preferences.

\begin{itemize}
    \item \texttt{set\_scope <core|fullchip>}: Selects the hardware hierarchy to simulate. Determines whether to instantiate a single core or the dual-core fullchip.
    \item \texttt{set\_sim\_stage <sim|gls|post\_sim>}: Sets the simulation backend.
    \begin{itemize}
        \item \texttt{sim}: RTL behavioral simulation.
        \item \texttt{gls}: Gate-level simulation using synthesized netlist.
        \item \texttt{post\_sim}: Post-PnR gate-level simulation with delay annotations via \texttt{xrun}.
    \end{itemize}
    \item \texttt{set\_clock\_period <ns0> [ns1]}: Configures the half-cycle clock periods. If \texttt{ns1} is omitted, it defaults to \texttt{ns0} (lockstep). Example: \texttt{set\_clock\_period 1 1.2}.
    \item \texttt{set\_dump\_vcd <0|1>}: Toggles waveform dumping (\texttt{1} for ON, \texttt{0} for OFF). Disabling VCD significantly speeds up massive test runs.
    \item \texttt{set VAR value}: Defines a shell variable that can be substituted later using \texttt{\$\{VAR\}}. Example: \texttt{set PATTERN sw/pattern/random100}.
    \item \texttt{fix\_set}: \textbf{Required.} Locks all configurations, triggers compilation of the hardware design, and transitions the shell into the execution phase.
\end{itemize}

\subsection{Phase 2: Hardware Execution Commands}
These commands are executed \textbf{after} \texttt{fix\_set}. They map directly to the unified controller interface of the chip.

\begin{itemize}
    \item \texttt{set\_exec\_target <MODE>}: Sets the execution mode of the hardware controller (mapped to \texttt{mode\_in}).
    \begin{itemize}
        \item \texttt{CORE\_MODE\_MULT\_save\_to\_PMEM}: Standard $Q \times K^T$.
        \item \texttt{CORE\_MODE\_MULT\_NORM\_save\_to\_PMEM\_and\_KMEM}: Computes $Q \times K^T$, applies Softmax, and saves to both Partial-Sum memory and Key memory for subsequent computation.
    \end{itemize}
    \item \textbf{Memory Writers}: Loads text-based integer matrices into the internal SRAMs via the \texttt{inst\_ext} and \texttt{mem\_in} ports.
    \begin{itemize}
        \item \texttt{writeQ <filepath>}: Loads data into QMEM.
        \item \texttt{writeK0 <filepath>}: Loads data into Core 0's KMEM.
        \item \texttt{writeK1 <filepath>}: Loads data into Core 1's KMEM.
    \end{itemize}
    \item \texttt{simulate}: Asserts the \texttt{start} signal and waits until the core's \texttt{status[3]} (busy flag) goes low. Internally, the testbench computes the golden model equivalent for validation.
    \item \textbf{Golden Checkers}: Reads out the data from the PMEM via the \texttt{inst\_ext} port and compares it against the golden model.
    \begin{itemize}
        \item \texttt{verifypmem}: Checks PMEM results for all active cores and prints PASS/FAIL statistics.
        \item \texttt{verifypmem0 / verifypmem1}: Specific checks for Core 0 or Core 1.
    \end{itemize}
    \item \texttt{reset}: Asserts the hardware reset signal for two cycles, clearing internal states.
    \item \texttt{for <var> = <start> to <end> ... endfor}: Iterates block of execution commands. Variables inside the loop can be referenced using \texttt{\$\{var\}}. Nested loops are not supported.
    \item \texttt{exit}: Terminates the simulation gracefully and prints a summary of mismatches.
\end{itemize}
